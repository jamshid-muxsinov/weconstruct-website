## 🚀 НАЧНИ РАЗРАБОТКУ ПРЯМО СЕЙЧАС

### Шаг 1: Запусти проект (1 минута)

```bash
# Перейди в папку проекта
cd /home/tasheet/development/sa_fastapi

# Запусти Docker Compose
docker compose up
```

**Что происходит:**
- Загружаются/пересобираются контейнеры (2-3 минуты если первый раз)
- PostgreSQL инициализируется
- Применяются миграции Alembic
- Uvicorn запускается с --reload
- Всё готово!

### Шаг 2: Открой приложение в браузере (30 секунд)

| Приложение | URL | Логин/Пароль |
|-----------|-----|---|
| Admin Panel (CRM) | http://localhost:8000 | admin / admin123 |
| Shop (Site) | http://localhost:8001/uz | - |

### Шаг 3: Начни менять код (15 секунд на изменение)

```bash
# Например, отредактируй файл
vim src/pages/shop_pages.py

# Сохрани (Ctrl+S)

# Смотри логи в другом терминале
docker compose logs -f admin

# Увидишь: "Reloading..." (200ms)

# Refresh браузер (F5) → видны изменения!
```

**Это всё!** Никаких docker compose build, никаких перезагрузок контейнеров!

## 🔍 КЛЮЧЕВОЕ ОБЪЯСНЕНИЕ

### Как это работает?

```
Docker Compose merge:

docker compose up
    ↓
Docker Compose загружает:
  1. docker-compose.yml (production конфиг)
  2. docker-compose.override.yml (если существует)
  3. Мержит (override переопределяет базовый конфиг)
    ↓
Результат на локальной машине:
  • Uvicorn вместо Gunicorn (для reload)
  • Bind mounts для кода (live changes)
  • Health checks отключены (для скорости)
    ↓
Результат на VDS:
  • override.yml НЕ существует
  • Используется только docker-compose.yml
  • Gunicorn, как в production
  • Всё работает как раньше ✅
```

### Почему это безопасно?

1. **docker-compose.override.yml в .gitignore**
   - На VDS этого файла нет
   - Не попадет в git push

2. **Production конфиги не менялись**
   - docker-compose.yml как был
   - Dockerfile как был
   - entrypoint.sh как был

3. **Zero-touch solution**
   - Только добавления, без замен
   - Production immutable
   - Полная совместимость

## ❓ ЧАСТО ЗАДАВАЕМЫЕ ВОПРОСЫ

### Q: Почему медленно загружается первый раз?
A: Docker собирает образ (~2-3 минуты). Это один раз. Потом быстро (200ms reload).

### Q: Как изменения кода появляются в контейнере?
A: Bind mount: `./src:/app/src` монтирует твою локальную папку в контейнер.

### Q: Почему production не сломается?
A: docker-compose.override.yml НЕ существует на VDS. Там используется только docker-compose.yml.

### Q: Что если я случайно изменю docker-compose.yml?
A: Используй `git diff docker-compose.yml` чтобы посмотреть изменения, и `git checkout docker-compose.yml` чтобы откатить.

### Q: Если БД поломалась?
A: `docker compose down -v && docker compose up` (потеряешь данные, но это dev).
